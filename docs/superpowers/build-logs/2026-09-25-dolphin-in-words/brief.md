# Brief: the dolphin in words — three small changes (2026-09-25)

Approved by Robin in chat. Bounded change, no plan document. Firmware repo /Users/robin/Downloads/flipper-access/Momentum-Firmware (branch screen-reader, head 08e80106f); project repo /Users/robin/Downloads/flipper-access (branch main, head 5241c42).

## Goal

With the home screen animations off, the dolphin's state reaches a blind user only through words. Three changes: the Passport's points line is spoken as "eighteen of one hundred" instead of "eighteen slash one hundred"; a level up is announced when it is granted ("Level up, level 4"); the status chord (Back and Down) says the level and the mood after the battery.

## Change 1: a slash between two numbers is "of"

File: `applications/services/screen_reader/speech_text.c`, the between-tokens branch (about line 524, `else if(c == '/') out_word(&o, "slash");`). When the slash sits between two digits, as the colon rule just above it checks with `between_digits`, say "of" instead of "slash": "18/100" becomes "eighteen of one hundred", "1/3" "one of three". A slash next to a letter stays "slash" ("/ext/apps" is "slash ext slash apps", "a/b" is "a slash b"). This is rule 14; add it to the rule list comment at the head of the file in the same style as the others.

Test first, in `tests/host/test_speech_text.c`: the existing expectation `expect("Mood: Happy. Level: 1. 18/100", "Mood, Happy. Level, one. eighteen slash one hundred")` changes to `"Mood, Happy. Level, one. eighteen of one hundred"`; add `expect("1/3", "one of three")`, `expect("/ext/apps", "slash ext slash apps")`, `expect("a/b", "a slash b")`, `expect("Max Level!", "Max Level!")`. Run `tools/run_host_tests.sh`: the text suite must fail on the changed expectation before the code change and pass after.

## Change 2: a level up is announced

The dolphin service (`applications/services/dolphin/dolphin.c`) publishes `DolphinPubsubEventUpdate` on a deed but nothing on a level change. In the `DolphinEventTypeLevel` branch, after `dolphin_state_increase_level`, publish the same event the deed branch publishes (two lines in the deed branch's shape). Nothing else in the dolphin service changes; the pubsub event enum stays as it is.

The reader (`applications/services/screen_reader/screen_reader.c`) subscribes to the dolphin's pubsub at service start: `furi_record_open(RECORD_DOLPHIN)` (it waits until the dolphin service has created its record during boot), `furi_pubsub_subscribe(dolphin_get_pubsub(dolphin), sr_dolphin_callback, sr)`, and reads the starting level once with `dolphin_stats` into a new field `uint8_t last_level`. The callback runs on the dolphin's thread and must do nothing but `furi_thread_flags_set(sr->thread_id, SR_FLAG_DOLPHIN)` (a new flag, `1 << 5`, added to `SR_FLAG_ALL`), exactly as `sr_desktop_status_callback` does for the desktop: `dolphin_stats` blocks on the dolphin's own event loop and would deadlock if called from its thread. In the service loop, on `SR_FLAG_DOLPHIN`, call `dolphin_stats` (the reader's thread may block briefly), and: if `stats.level > sr->last_level`, announce "Level up, level N" and set `last_level`; if lower (Momentum's Misc, Dolphin screen can set the level by hand), just set `last_level`. The announcement is never delayed and does not interrupt what is being said (it queues behind it), like "Unlocked": give it its own kind `SrAnnLevel` in the announcement kinds (so `sr watch` labels it right, and the throttle rules keep it undelayed as they do for lock announcements), and route it through `sr_announce` under the mutex like the lock announcements do; if the existing helper `sr_say_lock` fits after a rename to something like `sr_say_event(sr, kind, text, interrupt)`, rename it rather than duplicating it.

## Change 3: the status chord says level and mood

In `screen_reader.c`, where `SrChordStatus` builds its text with `sr_status_text(screen, text, SR_DESCRIBE_TEXT_MAX)` (about line 357), append the dolphin part on the reader's thread: `dolphin_stats` (blocking is fine here), then ", level N, mood happy" where the mood is happy when `butthurt <= 4`, okay when `<= 9`, else angry, the same thresholds as the Passport app (`applications/settings/dolphin_passport/passport.c:41-49`; say so in a comment; the Passport is a separate app on the card, so the three constants live twice on purpose). When the battery part is empty the text is just the dolphin part ("level 3, mood happy"); "No status bar" is no longer said. `sr_status_text` in `screen_model.c` stays pure and unchanged.
