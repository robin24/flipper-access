## Change A: Back and Down held long toggles the screen reader

Today Back held with a short Down reads the status bar (`SrChordStatus`), and Back with OK splits short (repeat) and long (spell) through the chord machine's long handling (`emit_long`). Add the same split to Down: Back held plus Down held long is `SrChordToggleReader`; Back plus a short Down stays the status. Mirror the OK logic exactly in `applications/services/screen_reader/sr_chords.c` (the pure state machine) and `sr_chords.h`, including which events are dropped and when the long is emitted, and cover it in `tests/host/test_sr_chords.c` first (the failing tests, then the code): Back press, Down press, Down long, Down release, Back release gives ToggleReader once and no Status; a short Down still gives Status; a Down long without Back is not a chord.

The reader must see this one chord while it is off. Today the input filter treats every key as ordinary when the reader is off. Change: the chord machine gets a mode (`sr_chords_feed` takes a `bool reader_on`, or a setter; pick what keeps the tests readable) in which only the Back-and-Down-long chord is recognised and every other key passes exactly as an ordinary key, including Back's own short and long; when the toggle chord fires in that mode, the drops are the same as in the on mode for that chord. Tests cover the off mode: Back plus Up passes everything unchanged; Back plus Down long toggles.

In `screen_reader.c`, on `SrChordToggleReader` (it runs on the reader's service thread like the other commands):
- Turning off: flip `momentum_settings.screen_reader` to false, `momentum_settings_save()`, turn the reader off the way `screen_reader_set_enabled(sr, false)` does, and then say "Screen reader off" through the speech engine directly (`speech_say`, interrupting), which plays although the reader is off, as `sr say` does.
- Turning on: flip the setting to true and save; enable the reader without its usual re-announcement of the screen; then say, as one utterance in parts (`speech_say_parts`), "Screen reader on. " followed by the same description Back and Up reads for the current screen (the ReadAll command's text), so the user hears the confirmation first and the screen right after it, in that order, with nothing cut. Mark the current screen as announced so the next frame does not read it again. If the screen description is empty, say "Screen reader on" alone.
- Never while the desktop is locked (the reader knows; the lock screen has its own Back handling): the command is ignored then.
- `sr chord downhold` runs it from the console, listed in the console's chord table and usage next to `okhold`.
- The Accessibility row and `sr on|off` keep working as today and stay in sync (they all read and write the same setting).

## Change B: the Passport's points line reads "experience 7 of 100 to level 3"

A tap note today has no position and is read after the title, before a screen's rows (`canvas_tap_hint_note`), so it cannot sit at the points line. Add a positioned variant to the GUI: `void canvas_tap_hint_note_at(Canvas* canvas, uint8_t x, uint8_t y, const char* text);` in `applications/services/gui/canvas.h` and `canvas.c`: the same record as a plain note (not drawn, `note` true, the secondary font, never the title) but with x and y set, so the screen model places it in reading order like drawn text, joining the row on that baseline after the text drawn to its left. In `applications/services/screen_reader/screen_model.c` (pure, host-tested) make a note with a position behave that way while a note at x 0, y 0 keeps today's behaviour (read first, a row of its own); add tests in `tests/host/test_screen_model.c` first: text "XP 7/100" at (59, 42) plus a positioned note "to level 3" at (100, 42) reads as one row "XP 7/100 to level 3"; a plain note still comes first; a positioned note is never the title. Read the model's row-joining rule before choosing the note's width handling (the model may need the note's text width like drawn text; say what you did).

The new function is exported: add its line to `targets/f7/api_symbols.csv` (`Function,+,canvas_tap_hint_note_at,void,"Canvas*, uint8_t, uint8_t, const char*"`, sorted where the other `canvas_tap_hint_*` entries sit) and bump `Version,+,87.2,,` to `Version,+,87.3,,`. The build's API check must then print "API version 87.3 is up to date"; if it prints anything else, stop and report exactly what. Apps built for 87.2 keep loading (a lower minor is fine), so only the Passport needs rebuilding: `./fbt fap_passport`, then copy `build/f7-firmware-C/.extapps/passport.fap` to `/ext/apps/assets/passport.fap` with `.venv/bin/python Momentum-Firmware/scripts/storage.py -p /dev/cu.usbmodemflip_Delphi1 send <local> <remote>` from the project root.

`applications/settings/dolphin_passport/passport.c`: after the points line is drawn (the `xp_str` string at x 59, y 42, in the font the passport sets for it), and only when the level is not the maximum (the "Max Level!" case draws no note), call `canvas_tap_hint_note_at(canvas, 59 + canvas_string_width(canvas, xp_str) + 2, 42, note)` where `note` is "to level N" with N the current level plus one (a small local buffer, `snprintf`). Nothing changes visually.
