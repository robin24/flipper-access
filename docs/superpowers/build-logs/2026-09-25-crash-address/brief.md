The device runs c502de5a (the comment-only commit after it needs no flash).

## Goal

Two things. (1) The device reboots now and then with the generic "furi_check failed" popup (twice today while idle, five or six times in all) and the crash handler prints its registers only to the debug UART, so nothing reaches the USB console. Keep the failing check's return address across the reboot and speak it in the crash popup, so the next crash names its line of code. (2) The Passport's points line is spoken as "seven of one hundred" with nothing saying what the numbers are; label it.

## Change 1: the crash address

- `furi/core/check.c`, `__furi_crash_implementation`, the release branch (`#ifdef FURI_NDEBUG ... else`, about line 178): right after `furi_hal_rtc_set_fault_data(ptr);` add `furi_hal_rtc_set_register(FuriHalRtcRegisterFaultLr, __furi_check_registers[12]);` with a comment: the lr the handler stored on entry (`GET_MESSAGE_AND_STORE_REGISTERS`, `str lr, [r12, #48]`, index 12) is the return address into the function whose check failed; `addr2line` on that build's `firmware.elf` names the line for an address in flash; an address in RAM (0x2000xxxx) is inside an app loaded from the card and needs that app's elf. The RTC backup register write is the same call `furi_hal_rtc_set_fault_data` makes, safe with interrupts disabled.
- `targets/f7/furi_hal/furi_hal_rtc.h` (or wherever the `FuriHalRtcRegister` enum lives; `grep -rn "FuriHalRtcRegisterFaultData" targets`): add `FuriHalRtcRegisterFaultLr, /**< Return address of the last failed check, 0 when none */` right before `FuriHalRtcRegisterMAX`. Read `furi_hal_rtc.c`'s init once: if a header field counts or checksums the registers, keep it consistent and say so in the report; the STM32WB55 has 20 backup registers, the enum is far below that.
- `applications/services/desktop/scenes/desktop_scene_fault.c`: the popup text becomes the message plus a second line "at 0803ABCD" (eight upper-case hex digits, `%08lX`, no `0x`: the reader spells a run of digits and letters character by character, and "at" gives the context). `popup_set_text` keeps the pointer, so build the text into a static buffer in that file (`static char desktop_fault_text[64]`), not a stack one. On exit the scene clears the fault data as today; it does not clear the address register, so the last crash's address stays readable until the next crash.
- `applications/services/screen_reader/screen_reader_cli.c`, `sr_cli_status`: after the "enabled" line print `last crash: at 0803ABCD` or `last crash: none` from `furi_hal_rtc_get_register(FuriHalRtcRegisterFaultLr)` (0 means none). Include the RTC header it needs.
- The address register is also a hint for the API CSV: the enum lives in an SDK header, so the build's API check may report the header changed or a new entry; adding a value to an enum changes no symbol, so expect "API version 87.2 is up to date"; if the check says otherwise, stop and report exactly what it printed.
