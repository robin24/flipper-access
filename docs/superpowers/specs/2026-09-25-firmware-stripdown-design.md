# Firmware stripdown design: memory plan steps 2 to 4, games out, SAM out

Date: 2026-09-25. Decisions taken with Robin on 2026-09-25: the API version stays 87.2, SAM leaves
the firmware, the Games category leaves the build and the card, no other category goes,
animations are off by default. This spec is the second and third step of the memory plan in
`docs/roadmap.md` (animations, the JavaScript engine, Sub-GHz back into flash), plus step 4
(SAM optional) taken all the way. The screen reader itself is described in
`docs/superpowers/specs/2026-09-22-flipper-screen-reader-design.md`; the recorded voice in
`docs/superpowers/specs/2026-09-24-clip-voice-design.md`.

## 1. Goal and scope

Sub-GHz must work with the reader on: today opening it restarts the device out of memory. The
firmware must keep a working flash margin for the reader's future features. The build must stop
producing what serves no blind user: the games, the JavaScript runner and its modules, SAM. The
home screen must stop loading animations by default. All of it with a delta that rebases onto
Momentum mechanically: removals through build configuration and manifests, a handful of guards,
and the removal of our own SAM port.

In scope: build options that exclude apps and categories; the JavaScript engine out of the
firmware and the CSV; Sub-GHz built into the firmware; SAM removed from the speech engine, the
settings, the console, the tests and the tools; a Momentum setting that keeps the desktop from
loading animations, off by default; the card cleaned by the updater; the measurements; the docs.

Out of scope: any other flash saving (asset-pack tables, the archive app on the card), reader RAM
trims beyond what SAM's removal gives, the release mechanics of the fork, pronunciation work.

## 2. Facts the design rests on

All measured on 2026-09-25 on the screen-reader branch at 22ae265ef, release configuration
(`COMPACT=1`, `DEBUG=0`, `-Os`, build directory `build/f7-firmware-C`), linker map summed per
library and per object with a script over `firmware.elf.map`, loaded sections only.

Flash. firmware.bin is 877,036 bytes against the 880,640-byte limit of the BLE stack (SFSA 0xD7),
3,604 spare. The largest groups: Sub-GHz protocol library 118,986; NFC library 114,963; hardware
layer 83,438; GUI service 54,256; compiled icons 50,428; JavaScript engine (`lib/mjs`) 41,111;
screen reader 35,073, of which SAM (`sam/sam.o`) 14,251; RFID library 35,027; loader 34,116, of
which the API symbol table (`firmware_api.o`) 25,574; toolbox 29,048; furi 23,852; C library
21,660; desktop 20,720; storage 18,783; archive 18,402; FatFs 17,195; RPC 12,354.

Static RAM (data plus bss): 9,580 bytes in total, of which SAM 3,704.

Throwaway builds on a temporary branch, deleted again, tree restored byte for byte:

- JavaScript engine out (library dropped from `lib/SConscript`, the 82 `js_`/`mjs_` functions
  and 8 `lib/mjs` headers dropped from the CSV, the JS apps not built): 835,780 bytes, a saving
  of 41,256. fbt printed "API version 87.2 is up to date" and every other fap linked without an
  import warning.
- Sub-GHz built in on top of that, with the manifest of commit 1c113c28a (the phase 2 attempt;
  the base d3f89dfe2 has not moved, so the file applies unchanged): 877,800 bytes, so Sub-GHz in
  flash costs 42,020 and leaves 2,840 spare. Static RAM plus 25 bytes.

Where the main apps live. On this Momentum base every main app is `MENUEXTERNAL`: NFC,
Infrared, RFID, iButton, GPIO, Bad KB, U2F and the Momentum settings app are faps on the card;
the firmware holds services and libraries. Loading a fap costs its image in RAM; Sub-GHz's is
about 55 KB, which with the reader's 27 KB left 2 KB in read mode on 2026-09-23 and restarts the
device now.

Animations. `desktop.c` unloads the animation before any app starts
(`DesktopGlobalBeforeAppStarted`, guarded by `animation_manager_is_animation_loaded`) and reloads
it after (`DesktopGlobalAfterAppFinished`). So animations cost RAM only at idle: 116 to 142 KB
free on 2026-09-22 depending on the animation, up to 26 KB. Each return to the home screen
reads the animation's frames from the card while the reader is opening clip files. The
Momentum settings are loaded in `furi/flipper.c` before any service starts.

Card. The on-device updater (`update_task_cleanup_resources` in
`applications/system/updater/util/update_task_worker_backup.c`) reads the previous `/ext/Manifest`
and removes every file, then every directory, that is not in the new resource manifest. The
resource manifest is generated by scanning `build/f7-firmware-C/resources`, and the build never
deletes stale outputs there or in `.extapps`. The current manifest lists 42 files under
`apps/Games/`, and 27 for `apps/Sub-GHz/subghz.fap`, `apps/assets/js_app.fap` and `apps/Scripts/`
together; the JS modules are under `apps_data/js_app/plugins/`, the console plugin under
`apps_data/cli/plugins/cli_js.fal`, the unit-test plugin under `apps_data/unit_tests/plugins/`.

Apps. All 204 faps on the card came from the build tree (polish round, Task 3: zero unmatched).
`applications/external` holds 245 apps; 42 have `fap_category="Games"` (956 KB on the card).
The JS runner `js_app` is `EXTERNAL`; `cli_js` is a `PLUGIN` that requires `cli`; the 30 modules
and the unit-test plugin `test_js` are plugins that require `js_app`. `AppBuildset._group_plugins`
in `scripts/fbt/appmanifest.py` drops a plugin whose parent is not built.

API. `scripts/fbt/sdk/cache.py` asks for a major bump only when an entry that is active in the
CSV disappears from the generated API. Entries deleted from the CSV by hand together with the code
they describe leave nothing to compare, so the version stays. No fap in the tree other than the
JS ones imports a `js_` or `mjs_` symbol (the throwaway build proved it). The loader resolves a
missing import with the "Missing Imports" dialog, and Momentum's loader offers "Continue anyways"
on a major mismatch; neither path is reached by anything shipped.

## 3. Build configuration: excluded apps and categories

Two new options in `fbt_options.py`, tracked, next to `SKIP_EXTERNAL` and `EXTRA_EXT_APPS`:

    # Left out of the build and of the card by the accessibility fork
    EXCLUDE_EXT_APPS = ["js_app", "cli_js"]
    EXCLUDE_EXT_CATEGORIES = ["Games"]

Plumbing mirrors `EXTRA_EXT_APPS`: declared in `site_scons/commandline.scons`, passed by
`firmware.scons` into the firmware environment, handed by `PrepareApplicationsBuild`
(`scripts/fbt_tools/fbt_apps.py`) to `filter_apps` and on to `AppBuildset` in
`scripts/fbt/appmanifest.py`. `_process_ext_apps` leaves out every external app whose appid is in
`EXCLUDE_EXT_APPS` or whose `fap_category` is in `EXCLUDE_EXT_CATEGORIES` before the target check,
so `_group_plugins` then drops their plugins by itself (`js_gui`, `js_event_loop`, the modules,
`test_js`). Rules: the filter applies to external, menu-external, plugin, debug and settings
types alike; an id in the list that matches no known app is reported once as a warning, not an
error, because the external tree may not contain it; the build prints how many apps the two
lists excluded, so a change in the count is visible. `scripts/ufbt/SConstruct` gets empty
defaults for both so ufbt keeps working, and `fbt_apps.py` reads them with a default of an
empty list. `FIRMWARE_APPS["unit_tests_min"]` loses its `js_app` line.

Not changed: `applications/system/js_app/` and `lib/mjs/` stay in the tree, the loader's and
the file browser's handling of `.js` files stays as inert code, the Games sources stay in the
`applications/external` submodule. Nothing is deleted from Momentum's tree.

## 4. JavaScript engine out; the API stays 87.2

`lib/SConscript` loses `"mjs"`. `targets/f7/api_symbols.csv` loses the 82 `Function` and
`Variable` lines whose name starts with `js_` or `mjs_` (regex `^(Function|Variable),[+-],m?js_`)
and the 8 `Header,+,lib/mjs/` lines; nothing else in the CSV changes, in particular the icon
variable `I_js_script_10px` stays because the icon is still compiled. The `Version` line stays
`87.2`. The build must print "API version 87.2 is up to date" and must not rewrite the CSV.

Why no major bump: the version rule exists to keep faps from resolving against an incompatible
firmware. Nothing shipped imports the removed symbols, the loader reports a missing import
honestly if a foreign fap ever does, and a bump to 88.0 would make the app catalog stop offering
builds for this firmware while protecting nobody. Robin decided to keep 87.2.

## 5. Sub-GHz built in

`applications/main/subghz/application.fam` becomes the version of commit 1c113c28a: `apptype`
`FlipperAppType.APP` with the explicit source list, because the firmware build hands every
`sources` entry to `GatherSources` on its own so a `!` exclude never meets `*.c`, and the Add
Manually scenes need the fap's define. The manifest comment may say "accessibility fork" instead
of "screen-reader branch"; otherwise the file is that commit's. The other apps in that manifest
(`subghz_add_manually`, the `cli_subghz` and `subghz_gps` plugins, the `subghz_load_extended_settings`
startup hook) are untouched and still built. No `subghz.fap` is produced. The main menu resolves
the entry by name, as the phase 2 device pass showed with `/int/.mainmenu_apps.txt`. The card's
`apps/Sub-GHz/subghz.fap` is removed by the updater (section 8).

## 6. SAM out: the speech engine after

What goes: `applications/services/screen_reader/sam/` (the port), every SAM path in `speech.c`
(`speech_sam_output`, `speech_sam_chunk`, `speech_sam_word`, `speech_sam_spell`, `SamVoice`,
`SPEECH_OVERHEAD_NS`), `speech_pcm_push` and the overhead argument of `speech_pcm_init` in
`speech_pcm.c` (`speech_pcm_push_raw`, the loudness table, the slot accumulator and
`speech_pcm_silence` stay, since the clips go through them), the rate: `speech_set_voice(rate,
volume)` becomes `speech_set_volume(volume)`, `momentum_settings.sr_rate` and the console command
`sr rate` and the "rate" figure of `sr status` go, the "Rate" and "Voice" rows of the
Accessibility scene and the list rebuild that showed Rate only with SAM go (rows left: Screen
reader, Volume, Verbosity, Change delay), `momentum_settings.sr_voice` goes (see below), the host
test `test_sam_port.c` with `sam_cases.h` and `sam_ref/`, the SAM reference build and diff in
`tools/run_host_tests.sh`, `tools/sam_calibrate.py`. `tools/say.sh` stays: it drives the external
Text to SAM demo app, which is Momentum's, not our port; the "Text to SAM" row of
`tools/ram_probe.py` stays for the same reason.

What the engine does afterwards, for a text item: the pronunciation layer (`speech_text`, its 13
rules, unchanged) yields words; each word plays its clip from the card; a word without a clip is
spelled with the letter clips, counted as a fallback word and logged to `/ext/sr/missing.txt` as
today; a letter whose clip is missing too is skipped after the letter gap, counted, and logged
once per boot like a word. A spelled item (`speech_say_spelled`) plays letter clips as today. The
chunking of a text into pieces of 80 (`SPEECH_CHUNK_MAX`) existed for SAM's 250-byte input; if the
word iteration needs no chunks it goes, and the item text of up to `SPEECH_TEXT_MAX` (800) is
walked in one pass; the reader's 160-byte queue texts and the parts of a long description are
unchanged either way.

Voice on and off: `sr voice on|off|status` stays, and `speech_set_voice_clips(false)` now means
mute: a text item with the voice off completes at once without opening any file, playing
anything, or writing the missing list; `sr voice status` counts such items under "muted". The
state is runtime only, on at boot, never saved: it exists as the guard `tools/voice_build.py`
places around a sync so the reader does not read clip files that are being replaced, and a
device that reboots during a sync must come back speaking. The generator's check of the status
reply ("voice on") keeps working unchanged.

Settings struct: `sr_rate` and `sr_voice` are removed from `MomentumSettings` and from the table
in `settings.c`; the remaining reader fields (`screen_reader`, `sr_volume`, `sr_verbosity`,
`sr_change_ms`) keep their order; `desktop_anims` (section 7) is appended at the end. Only our
own fields move, so no fap outside this tree reads a shifted field; the settings app and the
firmware are rebuilt together. A settings file that still carries `sr_rate` or `sr_voice` lines
loads fine, because the loader reads the keys it knows and ignores the rest, and the next save
drops them.

Without a card, or without `/ext/sr/voice`, the device is now silent, where SAM used to speak.
Robin accepted this: on this base a device without a card has no main apps either, and the
vocabulary is part of the card payload the fork ships.

## 7. Animations off by default

A new Momentum setting `bool desktop_anims` (file key `desktop_anims`, like Momentum's
`cycle_anims`), appended to `MomentumSettings` and to the settings table, default `false`. The
Momentum settings app shows it under Interface, Graphics as the first row, "Animations" with
values OFF and ON; changing it sets `save_settings` and `require_reboot`, so the app shows
Momentum's "Rebooting..." popup on exit and reboots, exactly like its other reboot-bound settings.
A reboot is required because the animation manager's state machine (`Idle`, `Blocked`,
`FreezedIdle`, `FreezedBlocked`) has no state for "never loaded", and
`animation_manager_load_and_continue_animation` crashes on an unknown state.

Guards in `applications/services/desktop/animations/animation_manager.c`, each a single early
return on `!momentum_settings.desktop_anims`, with one addition:

- `animation_manager_alloc`: skip the initial blocking check and the first idle animation, so
  nothing is ever loaded, no timer runs, and the bubble view stays empty (it draws nothing while
  its animation is NULL).
- `animation_manager_check_blocking_process`: return, but first apply a pending level-up
  (`dolphin_stats().level_up_is_pending` then `dolphin_upgrade_level`), because with animations the
  level is granted when the user presses a key on the "new mail" animation, which now never
  shows. The manager is asked to look at the dolphin's state after every deed and every storage
  event, so a pending level is granted at the next of those, not at boot: nothing runs against
  the dolphin while the desktop is still being set up. A blind user gets nothing from the mail
  animation anyway, and the passport keeps showing the level.
- `animation_manager_new_idle_process`, `animation_manager_unload_and_stall_animation`,
  `animation_manager_load_and_continue_animation`: return.
- `animation_manager_interact_process`: return false (the key is not consumed).

`desktop.c` needs no change: both of its unload calls are already guarded by
`animation_manager_is_animation_loaded`, which is false. The blocking animations for a missing
or bad SD card, the missing database, the URL screen and low battery never show either; none of
them carries text the reader would have read. The lock screen, the lock menu, the PIN entry and
their announcements are unchanged. With no bubbles, the desktop produces no same-screen changes,
so the reader's two-second quiet window after a key press has nothing to hold back; "Home
screen" is still spoken when the desktop appears without text, because the model announces the
desktop layer, not a bubble. The external animation files keep shipping in the resources and stay
on the card: dropping them would be a change to Momentum's assets for no memory gain.

Cost: at idle, 10 to 26 KB of heap stay free that the animation used, and returning to the home
screen reads nothing from the card. In apps, nothing changes, since the animation was unloaded
there already.

## 8. The card after the first full flash

The updater removes what the new manifest no longer lists: the 42 game faps and `apps/Games/`,
`apps/Scripts/` with its examples, `apps/assets/js_app.fap`, `apps_data/js_app/plugins/*.fal`
and the directory, `apps_data/cli/plugins/cli_js.fal`, `apps_data/unit_tests/plugins/test_js.fal`,
`apps/Sub-GHz/subghz.fap`. It leaves what was never in a manifest: `/ext/sr/voice`, Robin's
captures, any `apps_data/<game>/` save files, the `.momentum_settings.txt`. The voice clips of
words that only games used stay in `voice/` and on the card; they are harmless and a later prune
can drop them.

For the cleanup to be right, the release build must start without stale outputs: delete
`build/f7-firmware-C/resources` and `build/f7-firmware-C/.extapps` before the build that makes the
update package, then check the generated `resources/Manifest` for `apps/Games/`, `apps/Scripts/`,
`js_app`, `cli_js`, `test_js` and `apps/Sub-GHz/subghz.fap`: none may appear. `apps_data/js_app`
must not appear as a directory entry either.

## 9. Memory and flash budget after the plan

Flash, predicted from the measurements: 877,800 bytes after the engine out and Sub-GHz in, minus
about 16 KB for SAM (14,251 for the synthesizer, the rest its paths in the engine and the
console), so roughly 862 KB and 18 KB spare. The setting and the guards cost a few hundred
bytes. `tools/flash_headroom.sh` is run after every firmware build and the figures are recorded.

RAM, predicted: static RAM drops by about 3.7 KB (SAM's tables), so idle heap gains the same;
animations off add 10 to 26 KB at idle. In Sub-GHz, the 55 KB fap image no longer sits in RAM,
so read mode should keep on the order of 45 KB free with the reader on instead of 2 KB, and the
frequency analyzer should run. NFC read, the heaviest app, gains only SAM's 3.7 KB (from about
20 KB free). Measured with `tools/ram_probe.py` after the flash (the Doom row is removed from
its list; the game is gone), and the idle heap with animations off and on, 30 seconds after boot
each, is recorded as well.

## 10. Failure handling and risks

- Stale build outputs would put the removed files back into the manifest: section 8's cleanup
  and check are mandatory before the flash.
- The CSV edit must remove exactly the JS lines; if fbt rewrites the CSV or reports anything but
  "up to date", stop and look.
- If the main menu did not resolve the built-in Sub-GHz (it did in phase 2), the fallback is
  `/int/.mainmenu_apps.txt`; the device pass checks the menu before anything else.
- The engine refactor is the one runtime risk: the host tests cover the voice module, the
  queue, the PCM stage and the text layer; the device pass speaks menus, spells, changes volume
  and runs the chords before the round is called done. Rollback is `./fbt flash_usb_full` of
  commit 22ae265ef, which also puts every removed file back on the card.
- A pending level-up is applied without an animation; if `dolphin_upgrade_level` ever refuses
  outside its normal flow, the level simply stays pending as today.
- The device may show the post-update splash after the flash; `sr screen` first, then Back.

## 11. Testing and verification

Host: `tools/run_host_tests.sh` stays green with the SAM suite removed, the PCM tests reduced
to the raw path and the chunking tests gone from `test_speech_text.c`; the build's exclusion
filter gets a plain Python test over synthetic manifests. The muted case and the missing-letter
rule live in the engine's worker, which needs the card and the DMA, so the muted case is
verified on the device (`sr voice off`, `sr say`, the muted count moves and nothing plays) and
the missing-letter rule by reading, since every synced vocabulary has every letter.

Build: `./fbt` prints "API version 87.2 is up to date" and only the two pre-existing external
manifest warnings; `./fbt lint` exit 0; `.extapps` holds no `js_*`, `cli_js`, `test_js` or
`subghz.fap` after a clean of `.extapps`; the manifest check of section 8 passes;
`tools/flash_headroom.sh` after each firmware step.

Device, after one full flash (`./fbt flash_usb_full`, about 7 minutes, the device rebuilt
apps included): `sr screen` first. Then: `sr status` without a rate figure; `sr say` speaks
clips; `sr voice off` then `sr say` plays nothing and the muted counter moves; `sr voice on`. The
main menu has Sub-GHz and it opens; `loader info` names it; read mode and the frequency analyzer
run with the reader on, heap sampled. The Apps browser lists no Games folder. `storage list` of
`/ext/apps`, `/ext/apps/Sub-GHz`, `/ext/apps/assets`, `/ext/apps_data` shows the files of section
8 gone. The Accessibility scene has four rows; Interface, Graphics has Animations OFF first;
turning it ON reboots the device and the home screen animates again; OFF again and reboot. Idle
heap recorded both ways. Leaving an app says "Home screen"; the lock menu, lock and unlock still
announce. `tools/ram_probe.py` full run recorded. Menus, a spelled focus (Back and OK long),
volume chords and a long description work. The device is left idle on the home screen, reader on,
voice on, speech idle, animations off, and the log capture restarted.

## 12. Documents

The main design spec gets section 18 "Stripdown as built" and a note at the head of section 8
that SAM left the firmware on 2026-09-25 with a pointer here; `docs/roadmap.md` marks memory
plan steps 2 to 4 done with the figures, drops the SAM licensing note and records the API
decision; the README's "Using it on the device" loses the Rate row, the Voice row and `sr rate`,

## 13. Sequence

1. Build options and exclusions (section 3): build, check `.extapps` and the manifest.
2. JavaScript engine out (section 4): build, headroom.
3. Sub-GHz built in (section 5): build, headroom.
4. SAM out (section 6): engine, settings, console, Accessibility scene, host tests, tools, build,
   headroom.
5. Animations setting and guards (section 7): build, headroom.
6. Clean, build the package, one full flash, the device pass of section 11, the measurements.
7. Documents (section 12).

Steps 1 to 5 change code without touching the device; the device is flashed once, and a second
time only if the device pass finds something to fix.
