Pull request 10 came after the install. It is Task 10b, from the branch claude/card-confirm-2026-10-13, which was cut from 023a22de7. It made the two changes that Robin asked for on 2026-10-13, when the install had gone through:
First, the card reader way asks before it writes to the card it found. It says the card's name, path, size and free space, and asks "Copy the voice onto it? [Y/n]". Enter, y and yes copy; n, no or no answer eject the card and end the install in one sentence. An answer that is neither yes nor no is asked again, and the second time the install says "Answer Y for yes or N for no." and asks only the short question, so that the computer's screen reader does not read the whole line about the card again. Commits ef4337cf4 (the install), c59d9325b (the README and the install protocol) and 552b32d78 (the short question).
Second, the README keeps the version written out, with no "latest" addresses and no renamed assets, since the Python installer will give way to the Electron app. A host test, tests/fbt/test_readme_version.py, fails when a release name in a code block of the README, in its inline code, or in the sentence that says "name version" followed by a version, is not the newest version in CHANGELOG.md, and a release candidate's name counts as wrong; the README says that each release's notes on GitHub give the commands for that release; and Making a release says in step 1 to update the README's commands with the changelog entry. Commits 1abe2390d (the code blocks), 16b04601e (the README and Making a release) and 09fcc96a1 (the inline code and the sentence).
The round after the review also changed one word in two documents, and the two comments in the install that say it: a card sold as 64 gigabytes reads about 64, a little less once formatted, instead of 64.0 (d03f7db06).
