Section: The settings after a card change or a format

The cause of the card change, from the code. furi/flipper.c sets skip_double_mount at a boot with a card, after loading the settings itself, to skip the mount event the storage service sent for that card. Since Momentum's 7db15e838, "Storage: Dont send mount event if SD mounted at boot", no such event comes, so the flag stays set and swallows the first real mount after the boot: the settings of a card put in are never read, and a save writes the ones in RAM over them. A format on the device changes the card's state inside sd_format_card, between two ticks of the storage service, so no unmount or mount event follows at all.

Section: The clip order

tools/voice_build.py's clip_order and spoken_first: the sync and tools/voice_pack.py write a set's clips with the base list first (tools/voice_words.txt: digits, letters, the reader's own words), then the firmware's own words by how often its texts use them, which the extraction now counts, ties sorted, then every other word sorted. The run with --extract keeps that list in the set's manifest.json as "first", for the runs without it and for the pack. A file sent again goes into the first free place in its folder (FatFs's dir_alloc), its old one in a folder without gaps, and a pack unpacked over an installed set rewrites its files in place, so only a new folder, a new card or a pack into an empty set takes the order in full; a --sync-all leaves a set already on the card in its order. New checks: clip_order and spoken_first, the extraction's counts, the sync's order of sends, and the pack's order of clips; against the tools before, the voice build test stopped at the missing clip_order, and the pack's check failed with the clips in alphabetical order. After: voice build 156 of 156 checks passed, voice pack 29 of 29.

The prune: tools/card_prune.py counts the packages of the claude/ work branches as the fork's own; its new check failed against the prefixes before. Its first run is in the section above.

Section: The espeak set rewritten in clip order

Before, on 2026-10-02 on 778d09f8, from the console, the 25 words of the open-time test and three sentences of 28 words:
espeak: median 51 ms, mean 54 ms, max 82 ms, over 40 ms: 21
espeak: underruns 18 over 3 sentences of 28 words

The clips exist only on the card, so they were copied to the Mac first. Over USB, through the storage protocol, at about 7 clips a second, the copy stopped after 3,833 clips: the device sent nothing for 30 seconds in the middle of a read_chunks. The device was up since the flash and answered at once afterwards, and the voice came back on; most likely a byte was lost on the link, from which the protocol cannot recover. A retry with a fresh session went on from there, but at Robin's suggestion the card went into the Mac's card reader instead, on 2026-10-03.

The card came up read-only ("Media Read-Only: Yes"): the microSD adapter's lock slider. Unlocked, the Mac listed all 64 folders with the same files in the same order as the Flipper's storage list, so the Mac sees the directory order too. card_rewrite.py, a scratch script not kept in the repository, copied the clips the USB copy had not reached, 5,348, checked every size, then rewrote each folder: every file removed, the folder removed and made again, the clips written in clip order, and the folder's listing checked against the order and the sizes. 10,526 clips in 163 s.

macOS left a ._ file of 4,096 bytes beside every file and folder it wrote: 10,526 in the clip folders, 64 beside them, and a .fseventsd folder at the card's root. The cause is the com.apple.provenance attribute, which this macOS gives every file a process of this session makes, and which exFAT can only keep in such a file; an exFAT disk image showed the same for Python's open() and for /bin/mkdir and /bin/cp, and xattr -d and -c cannot remove it. With them, the opens were:
espeak: median 26 ms, mean 31 ms, max 87 ms, over 40 ms: 5
dot_clean_card.py, another scratch script, removed them through the Flipper, every name starting with ._ in the set and the folder .fseventsd, 10,608 files in 592 s; none is left. Their places stay as free entries between the clips.
